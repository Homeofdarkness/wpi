# Настраиваемая торговля ресурсами

Детальные импортные и экспортные сделки хранятся в отдельном опциональном
`trade.toml`. Они не заменяют существующую общую торговую прибыль: движок
показывает денежный результат настроенных сделок отдельной строкой бюджета.

У каждой страны собственный список сделок. Полей `country`, `partner` и
обязательного зеркального договора нет: конфигурация описывает только то, что
поставляется по договору и чем за это платят. Одинаковые условия можно
скопировать обеим странам и поменять только `direction`.

## Формат

```toml
schema_version = 2

[[deals]]
id = "water_for_copper"
direction = "import"
delivery = { target = "resource:fresh_water", amount_per_month = 300.0 }
payment = { target = "resource:copper", amount_per_month = 50.0 }

[[deals]]
id = "silver_purchase"
direction = "import"
delivery = { target = "resource:silver", amount_per_month = 40.0 }
payment = { target = "money", amount_per_month = 100.0 }

[[deals]]
id = "fuel_export"
direction = "export"
delivery = { target = "group:hydrocarbons", amount_per_month = 120.0 }
payment = { target = "money", amount_per_month = 90.0 }
```

Поля одной сделки:

| Поле | Значение |
| --- | --- |
| `id` | Уникальный alias внутри этого файла |
| `direction` | Роль текущей страны: `import` или `export` |
| `active` | Необязательное включение сделки, по умолчанию `true` |
| `delivery` | Предмет поставки от экспортёра к импортёру |
| `payment` | Оплата от импортёра экспортёру: деньги, ресурс или группа |
| `amount_per_month` | Месячная норма; движок умножает её на длительность хода |

Допустимые цели:

- `resource:<alias>` — конкретный зарегистрированный ресурс;
- `group:<alias>` — зарегистрированные ресурсы фиксированной группы;
- `money` — единицы валюты.

`delivery` всегда является ресурсом или группой. `payment` может быть
ресурсной — для бартера — либо денежной. Смысл полей не меняется между
странами:

| `direction` | Текущая страна получает | Текущая страна отдаёт |
| --- | --- | --- |
| `import` | `delivery` | `payment` |
| `export` | `payment` | `delivery` |

Например, договор «300 воды за 50 меди» у импортёра и экспортёра содержит
одинаковые `delivery` и `payment`; отличается только `direction`.

## Порядок расчёта

1. Импорт поступает до внутреннего потребления и может закрыть дефицит этого
   же хода.
2. Добыча, производство и внутреннее потребление выполняются как обычно.
3. Экспорт забирает только оставшиеся на складе ресурсы.
4. Денежный баланс сделок добавляется в бюджетный реестр отдельной строкой.

Объём исполнения зависит от эффективности торговли и перегрузки путей. Если
для отдачи не хватает ресурса или для получения нет места на складе, обе
стороны сделки пропорционально уменьшаются: страна не платит полностью за
частично доставленный товар.

Маршрутный коэффициент можно проверить вручную:

```text
надёжность = 0.55 + 0.45 × эффективность_торговли / 100
загрузка = используемые_пути / max(торговый_потенциал, 1)
перегрузка = 1 / (1 + 0.75 × max(загрузка - 1, 0))
исполнение_маршрута = надёжность × перегрузка
```

После этого исполнение дополнительно ограничивается доступным запасом для
локальной отдачи и свободной вместимостью для локального получения.

При импорте группы поставка сначала закрывает текущую потребность ресурсов с
наибольшим дефицитом, затем заполняет свободные склады. При экспорте группы
первыми уходят ресурсы с наибольшим остатком.

Денежный импорт учитывает курс и защищённую вальжерией долю расчётов.
Денежный экспорт дополнительно учитывает автоматически рассчитанное качество
товаров после промышленной напряжённости. Бартерные количества курс не
изменяет.

```text
защищённая_доля = вальжерия / 100
валютный_множитель = защищённая_доля
  + (1 - защищённая_доля) / курс

стоимость импорта = деньги_по_договору / валютный_множитель
доход экспорта = деньги_по_договору × валютный_множитель × качество

качество = 1.25 × доля_высокого
  + 1.00 × доля_среднего
  + 0.75 × доля_низкого
```

Доли качества в последней формуле нормализованы к единице. В отчёте поэтому
отдельно показаны договорная денежная величина и фактический денежный
результат после курса и качества.

## Запуск из файла

```powershell
uv run python create_basic_country.py `
  "test_files\edem_country_input.txt" `
  --trade-settings "test_files\trade_settings_example.toml" `
  --turns 1 `
  --seed 1
```

Основной результат содержит отдельный отчёт `ТОРГОВЫЕ СДЕЛКИ`. Рядом с ним
создаётся `*_trade_settings.toml`, который можно использовать на следующем
ходе. Полный готовый пример находится в
`test_files/trade_settings_example.toml`.

## Переход с экспериментальной версии 1

Версия 1 использовала неоднозначные локальные поля `give` и `receive`. В
версии 2 они удалены. Для старого импорта перенос выглядит так:

```text
give    → payment
receive → delivery
```

Для старого экспорта:

```text
give    → delivery
receive → payment
```

После переименования установите `schema_version = 2`. Парсер версии 2
специально отклоняет старую схему с понятным сообщением, чтобы направление
сделки не могло незаметно перевернуться.
