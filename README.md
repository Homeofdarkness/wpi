# WPI

Консольный движок пошаговой симуляции государства. Поддерживаются три
набора правил: `basic`, `atterium` и `isf`.

## Запуск

Требуется Python 3.11+ и [uv](https://docs.astral.sh/uv/).

```bash
uv sync --dev
uv run python main.py
```

Логгер не устанавливает консольный `StreamHandler`: в терминал попадает только
явный пользовательский вывод программы. Для записи диагностических логов в
файлы включите `WPI_LOG_TO_FILE=1`; каталог задаётся через `WPI_LOG_DIR`.

Создание базовой страны без ручного консольного ввода:

```bash
uv run python create_basic_country.py
```

По умолчанию скрипт читает `test_files/edem_country_input.txt` и сохраняет
стату в `test_files/edem_country_output.txt`, а редактируемые настройки — в
`test_files/edem_country_output_industry_settings.toml`.
Основной выходной файл также показывает все настроенные промышленные эффекты;
без расчёта хода они помечены как ожидающие.

Создать страну и сразу действительно пропустить один ход:

```bash
uv run python create_basic_country.py --turns 1 --seed 1
```

Подключить независимые импортные, экспортные и бартерные сделки:

```bash
uv run python create_basic_country.py \
  --trade-settings test_files/trade_settings_example.toml \
  --turns 1 --seed 1
```

`--turns` можно увеличить; `--seed` необязателен и нужен для воспроизводимости.
При расчёте выводятся отдельные отчёты бюджета и формирования прироста.
Производство, изменение склада и эффекты выполняются только при расчёте хода.

Приложение последовательно предлагает выбрать мир и способ ввода:

- `country_creator` — заполнить обязательные поля и затем вставить TOML
  ресурсов, добычи, производства и ресурсных эффектов;
- `moves_skipper` — отдельно вставить статы и настройки промышленности.

`moves_skipper` принимает шесть блоков: экономику с торговлей, промышленность,
её настройки, сельское хозяйство, государство с контролем и народом и
опциональный отдельный TOML торговли. Новый
ограждённый Markdown-блок читается целиком вместе с внутренними пустыми
строками. Ввод без рамки тоже сохраняет внутренние пустые строки и завершается
Enter после распознанных финальных полей; две пустые строки подряд служат
аварийным завершением старого неполного блока.
Проверенные чистые входные блоки находятся в
`test_files/moves_skipper_example`. Сокращённый реальный результат одного хода
с отчётом доходов и расходов приведён в
`test_files/edem_turn_output_example.txt`.

## Проверки

```bash
uv run ruff check .
uv run ruff format --check .
uv run pytest -q
```

Тесты фиксируют результаты полного хода во всех мирах, проверяют чтение
старого формата и основные инварианты бюджета, населения, инфляции,
продовольствия, ресурсов, производственных цепочек и вероятностей.

По умолчанию один ход равен трём месяцам. Чтобы изменить его длительность,
достаточно поменять только `TURN_MONTHS` в `functions/time_models.py`, например
на `9`: календарь автоматически пересчитает годы, финансовые потоки,
продовольствие, демографию, вероятности, складские потери, производство и сроки
правил. `consumption_per_month` в TOML является месячной нормой и умножается
на число месяцев хода; остальные исторические потоки масштабируются
относительно шестимесячного периода.

Промышленная модель поддерживает произвольные ресурсы, фиксированные
добывающие группы, автоматически распределяемую рабочую силу, склады,
дефициты, пять технологических укладов добычи от `manual` до
`mass_production`, производство и безопасные TOML-эффекты на любые числовые
статы, включая вероятности и показатели конкретных режимов. После хода
автоматически выводятся промышленный уклад, распределение добывающей мощности,
межсистемная промышленная готовность и напряжённость, материальный баланс,
ограничения формулы и производственные цепочки; новых полей TOML для этого не
требуется. `stage` меняет выпуск, долю населения в промышленности и долю
промышленного пула в добыче, а готовность отдельно учитывает технологии,
кадры, инфраструктуру, ресурсы, институты и рынок.
`availability` допускает богатые месторождения до 200% и реально масштабирует
добычу. Приоритеты автоматически сочетаются с текущей потребностью: при
дефиците часть мощности уходит на недостающие ресурсы, но настройки игрока
всегда сохраняют не менее 40% влияния. Группы `fertilizers` и
`agricultural_tools` автоматически связывают
ресурсный баланс с обеспеченностью сельского хозяйства, а качество товаров
после хода полностью выводится из промышленной готовности.
