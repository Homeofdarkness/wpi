# WPI: руководство по программе и формулам

Это руководство описывает текущее поведение программы по исходному коду.
Оно отделяет вводимые значения от производных и прямо отмечает параметры,
которые пока только показываются, но не участвуют в расчётах.

## 1. Быстрый старт

Требуется Python 3.11+ и `uv`.

```bash
uv sync --group dev
uv run python main.py
```

Служебный логгер не пишет в консоль и не дублирует пользовательские отчёты.
Файловые логи включаются отдельно через `WPI_LOG_TO_FILE=1` и сохраняются в
`WPI_LOG_DIR` (по умолчанию `logs`).

Программа сначала предлагает режим мира, затем способ ввода:

- `basic` — базовые правила;
- `atterium` — правила Аттериума;
- `isf` — правила Империи Серебряного Феникса;
- `country_creator` — последовательный ввод исходной страны;
- `moves_skipper` — чтение уже оформленных стат и расчёт следующего хода.

По умолчанию один ход равен **3 месяцам** (`0.25` года). Единственная
настройка длительности — `TURN_MONTHS` в `functions/time_models.py`; добыча
внутри хода разбивается на указанное число месячных подшагов.

Для создания базовой страны из файла без ручного ввода:

```bash
uv run python create_basic_country.py
```

По умолчанию читается `test_files/edem_country_input.txt`. Скрипт создаёт два
файла:

- `edem_country_output.txt` — пользовательская стата и состояние складов;
- `edem_country_output_industry_settings.toml` — переносимые настройки
  ресурсов, добычи, производства и эффектов в TOML.

`moves_skipper` использует пять содержательных точек ввода. Ограждённый блок
читается до закрывающей Markdown-рамки. Текст без рамки читается до финальных
полей своей секции: одиночные внутренние пустые строки сохраняются, а после
последней строки нужно нажать Enter. Две пустые строки подряд принудительно
завершают старый неполный формат.
TOML промышленности вставляется **отдельно** от основной промышленной статы.
В ограждённом блоке ввод заканчивается закрывающей рамкой, без рамки — двумя
пустыми строками. После хода программа отдельно печатает:

1. отчёт бюджета и подробный отчёт формирования прироста;
2. итоговую стату;
3. отчёт о выполнении производства;
4. настройки промышленности для следующего хода с уменьшенными сроками
   правил.

Для следующего хода нужно переносить и итоговую стату, и последний TOML-блок,
начинающийся с `schema_version = 3`. Старый отмеченный YAML v2 принимается
только для миграции; JSON- и старый строковый форматы не поддерживаются.

Текущий вывод объединяет экономику с торговлей, а государство с контролем и
народом. Поэтому отдельные дублирующие приглашения `ТОРГОВЛЯ` и `НАРОД`
удалены:

| Приглашение | Что вставить |
| --- | --- |
| `ЭКОНОМИКА` | Первый блок целиком, включая торговлю и филиалы |
| `ПРОМЫШЛЕННОСТЬ` | Весь блок промышленности с состоянием ресурсов |
| `TOML ПРОМЫШЛЕННОСТИ` | Отдельный TOML-блок; без Markdown-рамки после него нужны две пустые строки |
| `СЕЛЬСКОЕ ХОЗЯЙСТВО` | Весь аграрный блок |
| `ГОСУДАРСТВО` | Весь блок государства, контроля и народа |

Готовые проверенные примеры лежат в `test_files/moves_skipper_example` и
пронумерованы ровно в порядке появления приглашений. Это чистое состояние до
первого хода, без ошибочного кредита. Сокращённый результат его обработки находится в
`test_files/edem_turn_output_example.txt`.

## 2. Типы значений

В таблицах используются три обозначения:

- **ввод** — задаётся человеком или внешней системой;
- **состояние** — задаётся в начале, а затем изменяется движком;
- **расчёт** — вычисляется автоматически; вручную введённое значение будет
  пересчитано или поле вообще не читается из красивого формата.

Все ресурсные значения во внешнем формате округляются до одного знака после
запятой. Внутренние вычисления используют `float` без такого округления.

## 3. Порядок одного хода

Порядок важен: производство использует уже добытое в этом же ходу сырьё, а
обычный расход ресурсов происходит после производства.

1. Производные значения пересчитываются из текущего первичного состояния.
2. Считаются логистические поправки, сельскохозяйственные рабочие и базовые
   коэффициенты.
3. Обновляются численность, здоровье и социальная поддержка промышленных
   работников.
4. Случайно выбираются шесть показателей надёжности систем.
5. Считаются сельское хозяйство, пища и запасы пищи.
6. Выполняются добыча, потери на складах, производственные правила и обычный
   расход ресурсов.
7. По полученному дефициту и профициту применяются TOML-эффекты.
8. Считаются прирост населения и смерти от голода.
9. Пересчитывается гражданская промышленность.
10. Считаются налоги, курс, торговля и бюджетный реестр.
11. Считаются информационные вероятности крупных событий.
12. Обновляются казна, стабильность, образование и ЗВО.
13. При отрицательной казне пользователю предлагается кредит.

Повторное использование одного `TurnEngine` поддерживается: перед каждым
ходом базовый прирост и доход филиалов обновляются заново и не накапливают
повторно коэффициенты прошлого хода.

### 3.1. Календарь и масштабирование

Исторический баланс формул и TOML-настроек задан для шестимесячного периода.
`TurnCalendar` автоматически вычисляет:

```text
годы хода = TURN_MONTHS / 12
масштаб потока = TURN_MONTHS / 6
```

По масштабу потока пересчитываются доходы, расходы, производство, потребление
еды, базовый прирост, ЗВО и прочие величины «за период». Ресурсное
`consumption_per_month` задаётся отдельно как месячная норма и умножается
непосредственно на `TURN_MONTHS`. Старое имя `consumption` поддерживается
только при чтении для совместимости.
Вероятности переводятся из годовой интенсивности по фактическим годам хода.
Складская сохранность, убыль и постепенное приближение стат компонуются, а не
умножаются линейно. Чтобы перейти, например, на девятимесячный ход, нужно
изменить только `TURN_MONTHS = 9` и перезапустить программу.

## 4. Экономика

### 4.1. Основные показатели

| Показатель | Тип | Как считается или задаётся | На что влияет |
| --- | --- | --- | --- |
| Население | состояние | Положительное целое. После хода уменьшается на УНЧС, растёт на рассчитанный прирост и может уменьшиться от голода | Налоги, базовый прирост, аграрные рабочие, потребление пищи и товаров, образование, промышленная рабочая сила |
| УНЧС | ввод | Целое от 0 до 5 | Полугодовая выживаемость `(1 - 0.01 × УНЧС)` возводится в степень `TURN_MONTHS / 6` |
| Прирост | расчёт | Базовый демографический прирост, затем произведение социальных, продовольственных и промышленных коэффициентов | Прибавляется к населению |
| Казна | состояние | Денежный запас страны | Участвует в курсе валюты; к ней прибавляется чистый доход хода |
| Предыдущая казна | расчёт | Казна перед ходом, показывается второй частью пары бюджета | Только аудит изменения |
| Экономическая стабильность | состояние | 0–100; обновляется в конце хода по соответствию аппарата и его эффективности | Курс валюты и итоговый множитель денежных доходов |
| Инфляция | ввод | 0–100% | Денежные доходы умножаются на `1 - инфляция/100`; расходы не уменьшаются |
| ДОХОДЫ | расчёт | Это именно налоговый доход, а не весь доход страны | Одна из частей валового дохода и вход курса валюты |
| Государственный долг | состояние | Неотрицательное значение; увеличивается при взятии кредита | Создаёт проценты в расходах |
| Ставка долга | ввод/состояние | 0–100% годовых | Процент за ход: `долг × ставка/100 × TURN_MONTHS/12` |
| Баланс ресурсов | ввод | Внешний денежный результат ресурсов | Без дополнительной формулы входит в валовой доход; это точка интеграции с внешней торговлей ресурсами |

### 4.2. Базовый прирост населения

Пусть `P` — население. Исторические коэффициенты задают прирост за полгода,
поэтому сначала считается
`P/1000 × k × TURN_MONTHS/6`:

| Население | `k` |
| --- | ---: |
| меньше 1 млн | 6.87 |
| 1–2.5 млн | 9.87 |
| 2.5–5.5 млн | 11.77 |
| 5.5–8 млн | 9.87 |
| больше 8 млн | 8.77 |

Затем базовый прирост последовательно умножается на:

- обеспеченность ТЖН: `1.1`, если ТЖН не меньше 100, иначе
  `0.004 × ТЖН + 0.66`;
- социально-медицинский коэффициент стабильности;
- коэффициент довольства `0.004 × довольство + 0.754`;
- эффект пропаганды многодетности `1 + 0.015 × пропаганда`;
- продовольственный коэффициент;
- `1 - упадок общества/100`;
- коэффициент пищевого разнообразия
  `0.9 + 0.22 × clamp(разнообразие, 0, 100)/100`.

После этого применяется УНЧС. При реальном дефиците пищи число людей под
риском пропорционально доле нехватки; смерти выбираются биномиально с базовой
вероятностью 12–36%, которую смягчает богатство биомов.

После каждого рассчитанного хода `ОТЧЁТ ПРИРОСТА НАСЕЛЕНИЯ` показывает
базовый прирост за длительность хода, суммарную поправку TOML-формул ресурсов, все семь
коэффициентов, итоговый прирост, убыль по УНЧС, смерти от недоедания и конечное
население. Поэтому итог можно восстановить без чтения кода.

### 4.3. Налоги

Общие вводимые поля:

| Показатель | Роль |
| --- | --- |
| УН | Ставка универсального налога; базовый доход насыщается, а не растёт линейно |
| Акцизы | Нелинейный акцизный доход; дополнительно зависит от ТНП |
| Дополнительные средства | Прямая прибавка к налоговой базе |
| Налог на предпринимательство / налог на малый бизнес | Ставка для доли предпринимателей |
| Налог на крупных предпринимателей / аристократию | Ставка, умножаемая на число крупных субъектов |

Базовая формула до модификаторов:

```text
универсальный = 1.9882 × УН / ((8 + УН) × 10) × население / 1000
акцизный       = акциз / (акциз + 100) × 2000
база_малых     = население × доля_предпринимателей / 1000 × 0.6
малый          = ставка_малых × база_малых / 3000
крупный        = ставка_крупных / 10 × число_крупных
налоговая_база = универсальный + акцизный + малый + крупный + доп.средства
```

В базовом режиме ставка малых дополнительно умножается на `1.1`, если расходы
на инфраструктуру выше ожидаемых, иначе на `0.85`. Ожидаемые расходы:
`floor(население/10000) × 0.34`. Универсальный налог умножается на культурный
коэффициент, акциз — на коэффициент ТНП.

Вся налоговая база затем умножается на:

- коэффициент довольства `0.005 × довольство + 0.528`;
- логистическую налоговую поправку;
- `1 + целостность_веры/5000`;
- `1 - паника/100`;
- режимные множители;
- `max(0, 1 - перепроизводство/100)`.

### 4.4. Государственные и прочие расходы

| Поле | Всегда входит в расходы | Дополнительное влияние |
| --- | --- | --- |
| Инфраструктура | да | Условие бонуса/штрафа налогу на малый бизнес; при достаточной общей логистике даёт скидку `10%` от расходов на инфраструктуру |
| Логистика | да | Вместе с числом и содержанием провинций образует логистические расходы |
| Госаппарат | да | Определяет ожидаемый размер аппарата и изменение стабильности |
| Ресурсодобыча | да | Национальная добывающая мощность `расход × 300` |
| Образование | да | Вместе с наукой двигает образованность |
| Здравоохранение | да | Здоровье промышленных рабочих, эпидемия населения и социальный коэффициент прироста |
| Охранные учреждения | да | Сейчас только расход |
| Социальная сфера | да | Социальная поддержка промышленных рабочих |
| Наука | да | Вместе с образованием двигает образованность |
| Субсидирование бизнеса | да | Сейчас только расход |
| Внешние расходы | да | Только расход |
| Оккупация | да | Только расход |
| Армия | да | Только расход |
| Военное производство | да | Увеличивает ЗВО на `траты × военная_эффективность / 50` |
| Флот | да | Сейчас только расход |

Логистические расходы равны:

```text
логистика + число_провинций × траты_на_провинцию
```

Ожидаемая логистика равна `20%` суммы массива государственных расходов. Если
фактическая логистика не меньше ожидаемой, бюджет получает скидку `10%`
расходов на инфраструктуру. Иначе налоги штрафуются на 10%.

Полная сумма расходов включает все четыре массива расходов, провинциальную
часть логистики, внешнее поле `waste`, аграрные ожидаемые траты, проценты по
долгу и содержание принуждённых рабочих; доход от редкой еды вычитается из
расходов.

### 4.5. Торговля и валюта

| Показатель | Тип | Расчёт и влияние |
| --- | --- | --- |
| Торговый ранг | ввод | Определяет торговый потенциал и доступные пути; участвует в курсе |
| Торговый потенциал | расчёт | При ранге `<7`: `3 + 2 × (ранг-2) × эффективность/100`; иначе `5 + 3 × (ранг-6) × эффективность/100` |
| Эффективность торговли | ввод | Торговый потенциал, торговая прибыль, курс и потребление товаров |
| Используемые пути | ввод | Загрузка, торговая прибыль, перепроизводство и потребление товаров |
| Загрузка путей | расчёт | `используемые / потенциал × 100%` |
| Транспортные издержки | ввод | Вычитаются из торговой формулы и входят в признаки курса как часть расходов |
| Доступные пути | расчёт | `5 + 3 × (ранг - 1)`; информационное значение, торговый ввод им не ограничивается |
| Высокое/среднее/низкое качество | ввод | Сумма обязана быть `100 ± 0.1`; качества имеют веса в торговой прибыли |
| Вальжерия | ввод | Доля торговли, защищённая от курсового штрафа при перегрузке |
| Аллегоризация | ввод, 0–100 | Отдельно меняет торговые доходы/филиалы и налоги/ПСС |
| Курс валюты | расчёт | Смешанная нормализованная и совместимая со старой модель, ограничена 1–5 |
| Торговая прибыль | расчёт | Доход от путей и качества минус издержки, затем штрафы перегрузки, курса и перепроизводства |

Нормальная оценка качества:
`2.6 × высокое + 1.8 × среднее + 1.0 × низкое`. При сильной перегрузке веса
плавно переходят к `2.25`, `1.55` и `0.72`. Базовая прибыль:

```text
используемые_пути / (38 + 20 × перегрузка)
+ качество × эффективность / (100 + 45 × перегрузка)
- транспортные_издержки
```

При использовании сверх потенциала добавляются гиперболический штраф и
валютная поправка. Результат не может стать отрицательным. После этого он
умножается на `max(0, 1 - перепроизводство/50)`: при 50% перепроизводства
торговый доход уже равен нулю.

Курс использует стабильность, налоговый доход, все расходы, казну, торговый
ранг, эффективность и перегрузку торговли, гражданскую эффективность,
эффективность аппарата, довольство, бедность, безработицу и баланс контроля.
Это диагностически важный список: изменение любого из этих полей может
изменить курс даже при неизменных торговых настройках.

### 4.6. Филиалы и итог бюджета

Доход филиалов до режимных поправок:

```text
число_филиалов × эффективность_филиалов / 10
```

Валовой доход хода:

```text
налоги + торговля + филиалы + ПСС + доход науки + баланс ресурсов
```

Эффективный доход:

```text
валовой × (1 - инфляция/100) × множитель_режима × множитель_стабильности
```

Чистый доход — эффективный доход минус полные расходы. Новая казна:
`старая казна + чистый доход + логистическая скидка`.

Если казна отрицательна, можно отказаться от кредита или назвать желаемую
итоговую казну. Кредит равен `дефицит + желаемая_казна` и целиком добавляется
к государственному долгу.

## 5. Промышленность: общие статы

| Показатель | Тип | Как считается или влияет |
| --- | --- | --- |
| Производство переработки | ввод, 0–100 | Вместе с использованием определяет баланс переработки и коэффициент производительности |
| Использование переработки | ввод, 0–100 | Баланс переработки, доступность оборудования и риск аварии |
| Эффективность добычи | ввод, 0–100 | Коэффициент производительности, технология добычи и надёжность оборудования/выхода |
| Собственная ресурсная база | ввод | Первая часть среднего обеспеченностей |
| Сырьё | ввод | Вторая часть среднего обеспеченностей |
| Рабочие | ввод | Третья часть среднего; также определяет автоматическое число обычных промышленных рабочих |
| Квалификация | ввод | Четвёртая часть среднего обеспеченностей |
| Коэффициент производительности | расчёт | Базовая производительность переработки |
| Обеспеченность сырьём гражданки | ввод/состояние | После расхода ресурсов усредняется с реальным процентом покрытия спроса |
| Стандартизация | ввод, 0–100 | Гражданская эффективность, выход годной продукции и риск аварии |
| Логистика предприятий | ввод, 0–100 | Усиливает гражданскую эффективность, сохранность перевозки и складов |
| ТЖН | ввод, 0–100 | Прирост населения, гражданское использование, потребление и перепроизводство |
| ТНП | ввод, 0–100 | Акцизы, гражданское использование, потребление и перепроизводство |
| Потребление товаров | расчёт | Используется при изменении перепроизводства |
| Эффективность гражданки | расчёт | Входит в курс валюты |
| Ожидаемые траты промышленности | расчёт | Используются в ПСС, но не добавляются в общий расход отдельной строкой |
| Перепроизводство | состояние, 0–100 | Меняется каждый ход и может снизить совокупный налоговый доход не более чем на 20%. Торговый доход от этой статы не зависит: его штрафует только реальная перегрузка торговых путей |
| Максимальный потенциал | расчёт | Используется в ПСС |
| Использование гражданки | расчёт | Среднее сырья, ТЖН и ТНП; используется в эффективности и ПСС |
| ПСС | расчёт | Промышленная часть валового дохода |
| Военная эффективность | ввод | Прирост ЗВО от военного производства |
| Активные ресурсы | расчёт | Число зарегистрированных ресурсов, информационное поле |
| Всего на складах | расчёт | Сумма содержимого всех зарегистрированных складов |
| Обычные рабочие | расчёт | Автоматическая рабочая сила добычи |
| Специалисты | расчёт | Автоматическая квалифицированная рабочая сила добычи |
| Принуждённые | состояние API | В красивых настройках не задаются; влияют на добычу, расходы и риски |

Для нормального красивого ввода список обеспеченностей должен содержать четыре
числа в порядке: ресурсная база, сырьё, рабочие, квалификация.

### 5.1. Производные формулы гражданской промышленности

Пусть `M` — целая часть среднего четырёх обеспеченностей, `P` — производство,
`U` — использование, `E` — эффективность добычи.

```text
base = (M + E) / 2
distance = hypot(100 - P, 100 - U) / 4
balance = 1 - abs(P - U) / max(P, U)
коэффициент = clamp((base - distance) × balance, 0, 100)
```

Если `P = U = 0`, коэффициент равен нулю.

```text
использование_гражданки = round((сырьё_гражданки + ТЖН + ТНП) / 3)
mean = (коэффициент + использование + стандартизация/1.35) / 2.5
макс_потенциал = (коэффициент + использование) / 1.8
ожидаемые_траты = mean × 0.3
штраф = clamp(floor((использование-макс_потенциал)/5) × 2, 0, 7)
база_эффективности = mean - штраф
```

Логистический множитель эффективности:

```text
1 + log(1 + min(логистика, 30))/10 + max(0, логистика - 30)/100
```

ПСС:

```text
max(0, среднее_госрасходов × 0.3 - ожидаемые_траты)
× макс_потенциал / max(использование_гражданки, 1e-9)
```

Потребление товаров возвращает денежное потребление и внутреннее напряжение.
В стате показывается потребление:

```text
base = население × 45 / 1000
tension = clamp(население/1000/пути × 12 - (ТЖН+ТНП)/население×1000, 0, 100)
потребление = base × эффективность_торговли × (1 + tension/200) / 1_000_000
```

Если используется не меньше 40 торговых путей, перепроизводство каждый ход
уменьшается на `пути/100`. Иначе оно меняется на `+0.5`, когда
`ТЖН + ТНП > потребление`, и на `-0.5` в обратном случае.

## 6. Ресурсы, склады и добыча

### 6.1. Что регистрирует пользователь

Регистрация ресурса означает, что страна умеет с ним работать. Отдельного
флага «включён» во внешнем интерфейсе нет. У ресурса задаются:

| Параметр | Значение |
| --- | --- |
| `name` | Отображаемое имя; alias берётся из имени TOML-таблицы |
| `group` | Одна из фиксированных групп движка |
| `availability` | 0–100; линейный множитель добычи |
| `quality` | 0–100; линейный множитель добычи |
| `consumption_per_month` | Норма расхода за один месяц; фактический расход равен `consumption_per_month × TURN_MONTHS` |
| `storage_capacity` | Максимальная вместимость; добыча и производство не могут превысить её |

Отдельного геологического «запаса» или неизвестного объёма месторождения нет.
В колонке `Склад` показывается `текущее количество / вместимость`. Текущее
количество переносится из состояния ресурсов, а вместимость — из настроек.

Ниже приведены встроенные alias для совместимости. Это не закрытый каталог:
в TOML можно зарегистрировать новый alias, имя и одну из фиксированных групп
без изменения Python-кода.

| Группа | Alias группы | Ресурсы и alias |
| --- | --- | --- |
| Лесное хозяйство | `forestry` | Дерево (`wood`), Экзотическая древесина (`exotic_wood`) |
| Пресная вода | `fresh_water` | Пресная вода (`fresh_water`) |
| Минеральная вода | `mineral_water` | Солёная и минеральная вода (`mineral_water`) |
| Драгоценные ресурсы | `precious` | Золото (`gold`), Серебро (`silver`), Драгоценные камни (`precious_stones`), Алмазы (`diamonds`) |
| Стратегические металлы | `strategic_metals` | Алюминий (`aluminum`), Титан (`titanium`), Хром (`chromium`), Литий (`lithium`), Никель (`nickel`) |
| Цветные металлы | `nonferrous` | Медь (`copper`), Остальные цветные металлы (`other_nonferrous`) |
| Чёрные металлы | `ferrous` | Железо (`iron`), Остальные чёрные металлы (`other_ferrous`) |
| Тяжёлые металлы | `heavy_metals` | Тяжёлые металлы (`heavy_metals`) |
| Химическое сырьё | `chemical` | Сера (`sulfur`), Кремний (`silicon`) |
| Строительные материалы | `construction` | Базовые стройматериалы (`basic_building_materials`), Дорогие стройматериалы (`expensive_building_materials`) |
| Твёрдое топливо | `solid_fuel` | Уголь (`coal`), Торф (`peat`) |
| Углеводороды | `hydrocarbons` | Нефть (`oil`), Газ (`gas`), Благородные газы (`noble_gases`) |
| Редкоземельные металлы | `rare_earth` | Редкоземельные металлы (`rare_earth_metals`) |
| Соли | `salts` | Каменная соль (`rock_salt`), Калийная соль (`potash_salt`) |
| Почвы | `soil` | Чернозём (`chernozem`) |
| Плантации | `plantations` | Каучук (`rubber`) |
| Переработка отходов | `recycling` | Шлак (`slag`), Биоотходы (`biowaste`) |
| Минералы | `minerals` | Минералы (`minerals`) |
| Уникальные ресурсы | `unique` | Кристалл ядра (`core_crystal`), Уникальные ресурсы (`unique_resources`) |

У ресурса больше нет скрытого типа. Если alias входит в `extraction`, он
добывается; если входит в выход `production`, он производится. Один ресурс
может участвовать в обоих механизмах.

### 6.2. Настройка добычи

Настройка не требует ручного числа техники или работников:

```toml
[extraction.ferrous]
intensity = 80
priority = 2

[extraction.iron]
intensity = 100
priority = 1
```

Ключ внутри `extraction` определяет группу или конкретный ресурс.
Индивидуальная операция исключает ресурс из групповой операции, поэтому
двойной добычи не возникает.

- `интенсивность` — используемая доля мощности данного направления, 0–100%;
- `приоритет` — целочисленное место в очереди: `1` является самым высоким;
  при последнем ранге `N` вес равен `N - priority + 1`.

Национальная мощность равна `расходы_на_ресурсодобычу × 300`. В базовом и ISF
режимах это четвёртый государственный расход, в Atterium — пятый. Мощность
делится по весам приоритетов, затем умножается на интенсивность. Операции без
свободного места на целевом складе не забирают долю мощности. Перед каждым
месячным подшагом мощность и работники распределяются заново.

Работники также делятся между операциями пропорционально их уже рассчитанным
мощностям. Обычные работники:

```text
round(население × 0.35 × обеспеченность_рабочими/100)
```

Потенциал специалистов:

```text
denominator = max(10 000, 100 000 - 1 000 × уровень_образования)
potential = население / denominator × 2^(образованность/10)
специалисты = min(potential, население × 0.15)
```

Эффективный труд:

```text
health = 0.4 + 0.6 × здоровье/100
social = 0.65 + 0.35 × соцподдержка/100
обычные = число × health × social × явка/100
специалисты = число × 2 × явка/100
принуждённые = число × 0.55
```

Здоровье и социальная поддержка не вводятся в текстовых настройках. Каждый
шестимесячный период они на четверть приближаются к целевым значениям;
фактическая доля за ход компонуется по `TURN_MONTHS`:

```text
здоровье_target = clamp(40 + здравоохранение_на_миллион×1.5 + min(еда,100)×0.25)
поддержка_target = clamp(35 + соцсфера_на_миллион×2 + довольство×0.3 - бедность×0.2)
```

Принуждённые рабочие доступны через Python API. Их содержание за ход:
`число / 10 000 × 0.1 ед.вал`; их доля повышает риски аварии и саботажа.

### 6.3. Формула добычи

Для каждого месячного шага:

```text
labor_factor = 1 - exp(-эффективный_труд / labor_scale)
production_factor = labor_factor^labor_weight × group_efficiency
добыча = мощность × (1/12 года) × production_factor
       × доступность × качество × эффективность_добычи
       × доступность_оборудования × выход_годной_продукции
```

Процентные множители в последней строке делятся на 100. Профили групп:

| Группа | Вес труда | Масштаб труда | Эффективность |
| --- | ---: | ---: | ---: |
| forestry | 0.60 | 8 000 | 1.00 |
| fresh_water | 0.25 | 5 000 | 1.00 |
| mineral_water | 0.30 | 5 000 | 1.00 |
| precious | 0.45 | 12 000 | 1.00 |
| strategic_metals | 0.35 | 14 000 | 1.00 |
| nonferrous | 0.40 | 12 000 | 1.00 |
| ferrous | 0.35 | 10 000 | 1.00 |
| heavy_metals | 0.30 | 15 000 | 1.00 |
| chemical | 0.35 | 8 000 | 1.00 |
| construction | 0.45 | 8 000 | 1.00 |
| solid_fuel | 0.45 | 11 000 | 1.00 |
| hydrocarbons | 0.20 | 6 000 | 1.00 |
| rare_earth | 0.30 | 16 000 | 1.00 |
| salts | 0.40 | 8 000 | 1.00 |
| soil | 0.65 | 6 000 | 1.00 |
| plantations | 0.70 | 7 000 | 1.00 |
| recycling | 0.50 | 6 000 | 1.00 |
| minerals | 0.40 | 10 000 | 1.00 |
| unique | 0.70 | 20 000 | 0.75 |

Внутри групповой операции мощность сначала распределяется по величине
`max(расход - склад, 0) + дефицит_прошлого_хода`. Если срочного спроса нет —
по свободному месту на складах.

После всех месячных подшагов ко всему содержимому складов применяется
случайная `Сохранность на складах`, скомпонованная под длительность хода.
Поэтому в отчёте `Добыто` может быть больше, чем чистое изменение склада.

### 6.4. Расход и дефицит

После производства каждый зарегистрированный `расход` списывается со склада.
Если ресурса мало, списывается всё доступное, остаток записывается в
`Дефицит`. Общая обеспеченность ресурсами:

```text
100 × фактически_списано / запрошено
```

Новая обеспеченность сырьём гражданской промышленности — среднее старой
обеспеченности и реального покрытия. Поэтому дефицит в этом же ходу уменьшает
гражданскую эффективность, влияет на курс и косвенно на бюджет.

## 7. Производственные правила

### 7.1. Формат

```toml
[[production]]
id = "iron_parts"
name = "Железные детали"
active = true
batches = 50
months = 18
inputs = { iron = 2 }
outputs = { basic_building_materials = 1 }
byproducts = { slag = 0.1 }
```

Можно создавать любое правило над любыми зарегистрированными материалами.
`id` стабилен и используется для замены правила. Один выход автоматически
означает ресурсную цель; несколько выходов должны относиться к одной группе.

| Параметр | Значение |
| --- | --- |
| `active` | `true` или `false` |
| `batches` | Желаемое число партий за эталонные шесть месяцев; за ход масштабируется по календарю |
| `months` | Неотрицательное целое или `null`; срок в календарных месяцах, уменьшается даже при нулевом выполнении |
| `inputs` | Словарь `alias: количество` на одну партию |
| `outputs` | Основная продукция на одну партию |
| `byproducts` | Побочная продукция на одну партию |

Два встроенных идентификатора автоматически знают рецепты, если правило
создаётся через Python API:

- `basic_building_materials`: `2 iron + 1 coal + 0.5 silicon → 2.5 basic_building_materials + 0.4 slag`;
- `expensive_building_materials`: `2 basic_building_materials + 0.5 copper + 0.5 aluminum → 1 expensive_building_materials + 0.2 slag`.

Во внешнем TOML входы и выходы всегда печатаются явно, поэтому правило
можно проверить и изменить без знания кода.

### 7.2. Выполнение

Фактическое число партий равно минимуму из:

- запрошенных партий;
- `остаток каждого входа / вход на партию`;
- `свободный склад каждого выхода / (выход на партию × процессный выход)`.

Входы списываются полностью на фактические партии. Основной выход умножается
на случайный `Выход годной продукции`. Обычные побочные продукты не
умножаются. Для шлака дополнительно создаётся вся негодная доля номинального
основного выхода.

Правило выполняется после добычи и складских потерь, но до обычного расхода.
После попытки выполнения срок уменьшается на `TURN_MONTHS`. При нуле правило
получает `active: false` и больше не выполняется. Устаревшее поле `turns`
читается как число шестимесячных периодов, но новый вывод использует `months`.

### 7.3. Почему правило могло «не выполняться»

После разделения основной статы и настроек старый запуск мог принять пустую
секцию настроек и создать промышленность без правил. Теперь это запрещено:
`moves_skipper` выдаёт явную ошибку и требует файл `*_industry_settings.toml`.
Основная стата с непустым `СОСТОЯНИЕМ РЕСУРСОВ` также не читается без блока
настроек.

После каждого хода проверяйте отдельный отчёт:

```text
ПРОИЗВОДСТВО ЗА ХОД
Железные детали [iron_parts]: план 25.0, выполнено 21.2 партий, осталось месяцев 9
  Взято: Железо 85.0
  Выпущено: Базовые стройматериалы 36.1
  Побочно: Шлак 10.6
```

Сообщения различаются:

- `Правила производства не загружены` — потерян или не передан блок настроек;
- `Нет активных правил производства` — все правила завершены;
- `Текущий ход ещё не рассчитывался` — правила есть, но движок ещё не запускался;
- `выполнено 0.0` — правило запускалось, но не хватило сырья, выходного склада
  или вместимости; незарегистрированные ссылки отбрасываются ещё при чтении с
  ошибкой.

Для следующего хода копируйте напечатанный блок настроек, а не первоначальный:
только в новом блоке сохранены уменьшенный срок и завершённый статус.

### 7.4. Эффекты ресурсов на статы

Эффекты описываются в том же TOML. В зависимости можно передать список
`resource` и `group`, а одна формула применяется к каждой цели из `targets`.
Внутри доступны только `target` и по два числа на объявленную зависимость:
`deficit` и `surplus`.

```toml
[[effects]]
id = "construction_infrastructure_expenses"
dependencies = [{ group = "construction" }]
targets = ["infrastructure_expenses"]
formula = "target * (0.4 * groups.construction.deficit - min(0.25 * groups.construction.surplus, 0.2))"

[[effects]]
id = "hydrocarbons_transport"
dependencies = [{ group = "hydrocarbons" }]
targets = ["logistic", "trade_efficiency"]
formula = "-target * groups.hydrocarbons.deficit * 0.08"

[[effects]]
id = "freshwater_society"
dependencies = [{ resource = "fresh_water" }]
targets = ["contentment", "food_diversity", "population_epidemic_chance"]
formula = "-target * resources.fresh_water.deficit * 0.05"
```

Формула возвращает прибавку, а не новое абсолютное значение. Доступны только
арифметика, `min`, `max` и `abs`; движок не использует `eval`.

В `targets` можно указать любую существующую числовую стату экономики,
промышленности, сельского хозяйства, государства или вероятностей. Уникальные
имена пишутся без раздела. Если имя повторяется, используется явный путь:
`industry.expected_wastes` либо `agriculture.expected_wastes`. Неизвестные
показатели, списки и вложенные объекты отклоняются до начала расчёта хода.

`population_growth` и `infrastructure_expenses` остаются специальными
совместимыми alias. Инфраструктурный эффект не меняет исходное поле расходов и
выводится отдельной строкой бюджетного отчёта. Целочисленные показатели
округляются; ограничения, заданные в модели поля, сохраняются автоматически.
Вероятности не выходят за диапазон 0–100, но казна по-прежнему может быть
отрицательной. Производные показатели изменяются после своего расчёта, поэтому
последующий пересчёт не затирает эффект.

### 8.2. Работники и расходы

Базовое число аграрных работников линейно интерполируется по точкам:

```text
0 → 5 000; 1 млн → 5 000; 10 млн → 100 000;
50 млн → 275 000; 125 млн → 500 000; 200 млн → 1 млн;
400 млн → 2 млн; 500 млн → 2.5 млн; выше → 5 млн
```

Текущая формула затем умножает базу на
`(1 - перераспределение/100) × (процент_рабочих/100)`. Значение `70`
означает 70% расчётной потребности в работниках, а `100` — полную
обеспеченность.

Стоимость одной из трёх обеспеченностей на рабочего ступенчатая:
`0.5` при 0–20, `0.75` при 20–40, `1` при 40–60, `1.5` при 60–80,
`2` при 80–100 и `3` выше 100. Ожидаемые траты:

```text
рабочие × сумма_трёх_стоимостей / 10000
× (1 + земледелие×0.0028)
× (1 + животноводство×0.005)
× (1 + иное×0.0035)
```

### 8.3. Производство, потребление и запасы пищи

```text
стоимость = сумма_трёх_стоимостей - 0.75
коэффициент = стоимость / 0.25 × 1.75
выпуск = рабочие/550 × (коэффициент + 10)
       × (1 + сверхплодородность/100)
       × (1 - хвори/100)
       × (1 - ненастья/100)
       + еда_из_среды

потребление = население/10000 × (2.5 + 0.1 × коэффициент_потребления)
продовольственный_баланс = выпуск - потребление
индекс_обеспеченности = выпуск / потребление × 100
```

Индекс безразмерный и показывается без знака процента. Абсолютный
`продовольственный_баланс` не выводится в публичную стату: он нужен движку для
пополнения запасов и расчёта голода.

Новый запас пищи:

```text
min(старый_запас + max(профицит - 400,
                       профицит × изъятие/100),
    содержание_хранилищ × 39)
```

При дефиците движок сначала расходует запас пищи. Если запас полностью
закрывает недостачу, индекс остаётся `100`; иначе индекс показывает реальную
долю покрытого потребления, а незакрытый абсолютный дефицит используется при
расчёте голода.

Пищевое разнообразие:

```text
clamp(
  богатство_биомов
  - (abs(земледелие-40) + abs(животноводство-40) + abs(иное-20)) / 3,
  0,
  100
)
```

Индекс больше не может стать отрицательным. Его влияние на прирост монотонно
и ограничено коэффициентом от `0.9` до `1.12`.

Эффективность и развитие используют `tanh` средней обеспеченности, штраф за
отклонение от структуры 40/40/20, отношение рабочих к населению, биомы,
болезни и разнообразие. Обе величины ограничены сверху 100%.

В ISF итоговая обеспеченность едой дополнительно умножается на
`1 - неосвоенность_Империи/100`.

Ожидаемый размер аппарата:

```text
миллионы = floor(население / 1 000 000)
x = расходы_аппарата × миллионы / 100
ожидаемый_размер = round(sigmoid(floor(x × 1000 / 13)) × 100)
```

В базовом и ISF расход аппарата — соответствующая одна строка. В Atterium
используется сумма федеративных и республиканских расходов.

Образованность обновляется в конце хода. Целевой уровень зависит от населения
и суммы расходов на образование и науку. При снижении разрыв сокращается
ступенчато на `floor(abs(разрыв)/8)`, при росте прибавка равна
`разрыв/max(текущая_образованность,1)`. После этого пересчитываются успех
исследований и упадок общества.

### 9.2. Контроль

Массив контроля всегда содержит четыре доли:

1. правящая сила / императорский двор;
2. представительство;
3. имеющие силу / аристократия;
4. автономии.

Сумма не нормализуется автоматически. Баланс
`control[0] + control[1] - control[2] - control[3]` влияет на курс и риск
сепаратистского кризиса.

В basic и Atterium, если первые две доли дают не меньше 90, эффективное
довольство получает `+5`, а налоговый штраф уменьшается на 5 п.п. Иначе
довольство получает `-5`, а налоговый штраф увеличивается на
`(третья + четвёртая)/400`.

В ISF условие исторически инвертировано: бонус применяется, когда первые две
доли **меньше** 90; одновременно продовольствие получает `-4`. При значении не
меньше 90 применяются штраф довольства и налоговая поправка. Для ISF доля
аристократии не может превышать 15.

```text
base = (уровень_образования + образованность) / 2
успех = clamp(base × (0.9 + 0.1 × стремление_к_эрудиции/100), 0, 100)
```

В basic упадок равен `clamp(negative - positive, 0, 100)`, где:

```text
positive = довольство×0.05 + доверие×0.15 + традиции×0.05
         + аскетизм×0.25 + образованность×0.05 + эрудиция×0.075
         + культура×0.05 + милость×0.7 + убеждённость×0.15

negative = насилие×0.5 + эгоцентризм×0.3
         + тунеядство×0.3 + отхождение×1.1
```

Atterium и ISF используют свои веса, перечисленные в разделе режимов.

## 10. Вероятностная модель

### 10.1. Надёжность систем

Каждый ход сначала считается среднее значение, затем фактический процент
выбирается из бета-распределения:

```text
p = clamp(mean/100, 1e-6, 1-1e-6)
X ~ Beta(p × 800, (1-p) × 800)
результат = 100 × X
```

Концентрация 800 даёт небольшое, но ненулевое колебание около среднего.
Генератор можно зафиксировать seed для воспроизводимых тестов.

| Стата | Среднее до случайности | Реальное влияние |
| --- | --- | --- |
| Доступность оборудования | `67 + 0.18×эфф.добычи + 0.13×стандартизация - 0.08×max(исп.переработки-80,0)` | Линейно умножает добычу; входит в риск аварии |
| Явка работников | `74 + 0.13×здоровье + 0.10×соцподдержка - 0.08×усталость` | Умножает обычный труд и специалистов |
| Выход годной продукции | `55 + 0.20×эфф.добычи + 0.25×стандартизация` | Умножает добычу и основной выпуск производства; брак превращается в дополнительный шлак |
| Сохранность при перевозке | `86 + 0.12×логистика - 0.04×сепаратизм - 0.025×усталость` | Сейчас прямо влияет только на вероятность нарушения снабжения, а не списывает груз |
| Сохранность на складах | `91 + 0.08×логистика` | Оставляет на каждом складе соответствующий процент перед производством |
| Воспроизводимость исследований | `25 + 0.20×уровень образования + 0.20×образованность + 0.12×эрудиция + 0.18×качество информации` | Информационная стата; автоматического исследования нет |

Все средние ограничиваются диапазоном 0–100.

### 10.2. Вероятности крупных событий

Крупные вероятности — **информация для ведущего или внешней системы**. Движок
не бросает кубик, не создаёт событие и не изменяет страну автоматически.

Сначала считается безразмерный риск `R`, затем годовая интенсивность `λ = cR`
переводится в вероятность за фактическую длительность хода:

```text
P = (1 - exp(-λ × TURN_MONTHS/12)) × 100%
```

| Событие | Риск `R` и коэффициент `c` |
| --- | --- |
| Промышленная авария | `R=0.55+1.6×использование²+1.4×(1-оборудование)+0.8×(1-стандартизация)+1.2×доля_принуждённых+1.0×(1-безопасность)`, `c=0.045` |
| Нарушение снабжения | `R=0.5+1.5×(1-сохранность_перевозки)+сепаратизм/80+усталость/150`, `c=0.035` |
| Эпидемия населения | `R=0.35+бедность/70+дефицит_еды+0.8×(1-качество_информации)+0.8×(1-защита_медицины)`, `c=0.025` |
| Сельскохозяйственная эпидемия | `R=0.4+хвори/35+max(0,60-разнообразие)/60+max(0,60-эффективность)/80`, `c=0.04` |
| Природное бедствие | `R=0.45+ненастья/30+max(0,40-биомы)/80`, `c=0.035` |
| Массовые протесты | `R=0.25+max(0,60-довольство)/35+max(0,60-доверие)/40+неравенство/100+поляризация/80+усталость/100`, `c=0.055` |
| Сепаратистский кризис | `R=0.2+сепаратизм/55+поляризация/130+max(0,-баланс_контроля)/50+max(0,1-поддержка_провинций)`, `c=0.04` |
| Крупный саботаж | `R=0.2+2.2×доля_принуждённых+насилие/100+поляризация/100+max(0,50-качество_информации)/70`, `c=0.035` |

В формулах аварии проценты использования, оборудования, стандартизации и
безопасности предварительно делятся на 100. Сейчас «безопасность» берётся из
той же стандартизации, поэтому она участвует в риске дважды. Это известная
особенность текущей реализации, а не скрытая отдельная стата.

## 11. Различия режимов

### 11.1. Basic

Использует описанные выше базовые налоги, basic-формулу упадка и предел
довольства 100. Доход науки существует отдельной статой. В контроле бонус
работает при сумме первых двух долей не меньше 90.

### 11.2. Atterium

Дополнительные экономические поля:

| Поле | Влияние |
| --- | --- |
| СиРМБ | Используется вместо ставки малого бизнеса; получает инфраструктурный и формационный множитель |
| Вложения крупных компаний | Используются вместо крупного налога: `значение × 0.35 × связь_Федерации×0.002` |
| Эффективность приказов Цесаркии | Добавляет `эффективность/80 × (Клюпр/4)` к налоговой базе |
| Эффект Адриана | Торговля умножается на `1 + 3×эффект/100`; налоги — на `1 + эффект/400` |
| Сила СЭЗ | Торговля, акциз и филиалы умножаются на `1 + сила/200`; малый бизнес — на `1 + сила/400` |

Универсальный налог дополнительно умножается на `0.7`. Число крупных субъектов
для налогов равно `Клюпр/4`. Эгоцентризм даёт множитель огромной экономики
`max(1, эгоцентризм×0.025)`.

Государственные расходы содержат пять позиций: инфраструктура, логистика,
федеративные, республиканские, ресурсодобыча. Добыча использует именно пятую
позицию; федеративные и республиканские вместе финансируют аппарат.

Дополнительные общественные поля:

- `Связь Федерации` — налоговый вклад крупных компаний и ожидаемый аппарат;
- `Капиталистическое разложение` — повышает упадок с весом `0.2`;
- `Равенство` — уменьшает упадок с весом `0.16`;
- `БТЗГ` — режимное имя эгоцентризма;
- `Клюпр Цесаркии` — режимное имя крупных субъектов.

Atterium-упадок:

```text
positive = довольство×.04 + доверие×.19 + традиции×.04 + аскетизм×.30
         + образованность×.04 + эрудиция×.074 + культура×.04
         + милость×.80 + убеждённость×.14 + равенство×.16
negative = насилие×.30 + БТЗГ×.15 + капразложение×.20
         + тунеядство×.15 + отхождение×.90
```

### 11.3. ISF

Экономически малый бизнес называется `Налог на малый бизнес`, а крупные
субъекты — `Налоги с аристократии`; базовая налоговая формула та же.

Особые поля:

| Поле | Влияние |
| --- | --- |
| Неосвоенность Империи | Уменьшает обеспеченность пищей на соответствующую долю |
| Влияние Аллегории | Добавляет к логистической поправке довольства `довольство×влияние/1000`; все денежные доходы умножает на `1-влияние/1000`; уменьшает упадок |
| Сила Имперского Двора | Уменьшает упадок |
| Милость Серебряной | Сильно уменьшает упадок |
| Сепаратизм Высших | Повышает упадок |

ISF-упадок:

```text
positive = довольство×.04 + доверие×.19 + Аллегория×.08 + традиции×.04
         + аскетизм×.30 + образованность×.05 + эрудиция×.075
         + культура×.05 + милость×.80 + убеждённость×.15 + двор×.15
negative = насилие×.30 + эгоцентризм×.15 + тунеядство×.15
         + отхождение×.90 + сепаратизм_Высших×.45
```

Предел довольства равен 125. Логика контроля отличается от basic и описана
в разделе 9.2.

## 12. Полный внешний формат промышленности

Настройки являются проверяемым TOML v3. Группы не регистрируются: их фиксированный
список всегда присутствует в состоянии. Ресурсы произвольны.

```toml
schema_version = 3
extraction = {}

[resources.reinforced_glass]
name = "Армированное стекло"
group = "construction"
availability = 72
quality = 81
consumption_per_month = 20
storage_capacity = 300

[[production]]
id = "reinforced_glass_production"
name = "Производство армированного стекла"
active = true
batches = 20
months = 24
inputs = { basic_building_materials = 2, silicon = 0.5 }
outputs = { reinforced_glass = 1 }
byproducts = { slag = 0.1 }

[[effects]]
id = "freshwater_population_growth"
dependencies = [{ resource = "fresh_water" }]
targets = ["population_growth"]
formula = "-target * resources.fresh_water.deficit * 0.2"
```

Неизвестные ключи запрещены. Alias соответствует
`[a-z][a-z0-9_]*`; все ссылки производства должны вести на ресурсы из того же
TOML. Детальная схема, формулы эффектов и пример Python API приведены в
`INDUSTRY.md`.

Начальное или перенесённое состояние:

```text
СОСТОЯНИЕ РЕСУРСОВ
Ресурс                            | Склад       | Добыто | Дефицит
--------------------------------- | ----------- | ------ | -------
Железо [iron]                     | 100 / 2000  | 0      | 0
Базовые стройматериалы [basic_building_materials] | 0 / 1000 | 0 | 0
Шлак [slag]                       | 0 / 500     | 0      | 0
```

Состояние входит в пользовательскую промышленную стату. Настройки и отчёт
производства остаются отдельными, поэтому TOML или служебные поля в основной
стате не показываются.

## 14. Что пока не влияет на симуляцию

Это не догадки, а список фактически неподключённых или только информационных
величин:

| Поле | Текущее состояние |
| --- | --- |
| Социальная мобильность | Хранится и выводится, формула хода не использует |
| Коррупция | Функция коэффициента существует, но не подключена |
| ЗВО | Накапливается, но военная модель его пока не расходует |
| Охранные учреждения, субсидии, армия, флот, внешние расходы, оккупация | Учитываются как расходы, но не дают дополнительного эффекта |
| Сохранность перевозки | Влияет на вероятность нарушения снабжения, но не уменьшает реальные грузы |
| Воспроизводимость исследований | Показывается, но не меняет `Успех исследования` и не запускает исследования |
| Все крупные вероятности | Не создают события автоматически |
| Доступные торговые пути | Информационны; `Исп. пути` ими не валидируется |

Отдельно стоит историческая несогласованность аграрного `Процента рабочих`:
формула использует его как прямой множитель. Изменять её без миграции старых
стат нельзя, иначе результаты стран изменятся примерно в сто раз.

## 15. Диагностика типичных проблем

### Производство не выполнилось

1. Убедитесь, что в секцию `=== TOML ПРОМЫШЛЕННОСТИ ===` вставлена полная
   конфигурация от `schema_version = 3` до конца файла.
2. Найдите правило в `ПРАВИЛА ПРОИЗВОДСТВА` и проверьте
   `active: true`, `months > 0` или `null`, `batches > 0`.
3. Проверьте регистрацию каждого входа, выхода и побочного ресурса.
4. Посмотрите отдельный отчёт: `выполнено 0.0` означает отсутствие сырья или
   свободного выходного склада.
5. Проверьте колонку склада: левое число — текущее содержимое, правое — предел.
6. Для следующего хода используйте напечатанные обновлённые настройки.

### Добыча равна нулю

Проверьте расходы на ресурсодобычу, ключ alias в `extraction`, интенсивность,
регистрацию ресурса и свободное место на складе. При нулевом бюджете
ресурсодобычи приоритет и работники сами по себе добычу не создают.

### Эффект отсутствует или не меняет стату

1. Найдите его `id` в разделе `ЭФФЕКТЫ ПРОМЫШЛЕННОСТИ` основного выхода.
2. Если написано `ожидает расчёта хода`, страна только создана; выполните
   `uv run python create_basic_country.py --turns 1 --seed 1`.
3. Если указано `(+0.0)`, эффект существует и был применён, но конкретная
   формула вернула нулевую поправку; проверьте дефицит и склад зависимости.
4. Полный TOML, включая `id`, `dependencies`, `targets` и формулу, находится
   в отдельном файле `*_industry_settings.toml`, а не внутри основной статы.
5. Если Pydantic разрешает только `population_growth` и
   `infrastructure_expenses`, запущена старая версия проекта или архив был
   распакован во вложенную папку вместо корня проекта.

### После вставки программа всё ещё ждёт ввод

Ограждённый Markdown-блок читается до закрывающей рамки. В блоке без рамки
одиночные внутренние пустые строки не завершают ввод; после финальной строки
TOML нужно нажать Enter дважды. В `country_creator` файл-скрипт подменяет
все вызовы `input()` ответами до блока промышленности; неправильное число
строк приводит к сообщению с названием следующего ожидаемого поля. Не
запускайте сам `main.py`, если хотите чтение ответов из файла: запускайте
`create_basic_country.py`.

### Остались лишние данные в input-файле

Обычные ответы должны идти до `schema_version = 3`. Дополнительные служебные
заголовки и строки начала/конца больше не нужны. Комментарии начинаются с `#`,
пустые строки игнорируются. Состояние ресурсов помещается после TOML и читается
отдельно.

## 16. API для интеграции

Минимальный программный запуск:

```python
from modules.mode_spec import GameMode, get_mode
from modules.run_skip_move import TurnEngine

spec = get_mode(GameMode.BASIC)
engine = TurnEngine(state=world_state, rules=spec.rules_factory())
report = engine.run()

print(report.ledger.gross_income)
print(report.total_wastes)
print(world_state.industry.render_production_results())
print(world_state.industry.render_configuration())
```

Ресурсы можно менять атомарными методами:

```python
transfer = industry.collect_resource(ResourceType.IRON, 100)
print(transfer.actual, transfer.overflow)

transfer = industry.spend_resource(ResourceType.IRON, 140)
print(transfer.actual, transfer.shortage)
```

Для регистрации используются `ResourceRegistration`,
`ExtractionOperation` и `ProductionRule`. Валидация запрещает отрицательные
количества, переполненное начальное состояние, неизвестные alias и ссылки на
незарегистрированные ресурсы.

`SkipMoveReport` содержит казну до/после, все категории доходов и расходов,
отдельную `resource_effect_wastes`, скидку логистики, изменение стабильности,
кредит и копию вероятностей. Полный
`TurnLedger` позволяет отдельно проверить валовой, эффективный и чистый доход.
