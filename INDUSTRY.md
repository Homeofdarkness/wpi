# Промышленность: TOML, ресурсы и эффекты

По умолчанию один ход равен трём месяцам, а его длительность задаётся единственной
константой `TURN_MONTHS` в `functions/time_models.py`. За ход движок выполняет
ровно столько месячных подшагов добычи, сколько указано в календаре, затем
производит ресурсы, покрывает расход и применяет ресурсные эффекты.

`consumption_per_month` задаётся **за один месяц**, поэтому фактический расход
за ход равен `consumption_per_month × TURN_MONTHS`. `batches` остаётся
производственной нормой
за исторический шестимесячный период и масштабируется как
`batches × TURN_MONTHS / 6`.

## Основные правила интерфейса

- группы фиксированы движком и всегда выводятся, даже если в группе нет
  ресурсов;
- alias ресурса не ограничен встроенным каталогом: допустим любой идентификатор
  вида `a_z0_9` с первой строчной буквой;
- у ресурса нет скрытого типа; добывается или производится он только потому,
  что на него ссылается соответствующее правило;
- содержимое склада является состоянием и находится в основной стате;
- вместимость склада, уклад, доступность, качество и расход являются
  настройками TOML;
- работников вручную распределять не нужно: движок считает общий промышленный
  пул и делит занятых между добычей и производственными цепочками.

## Минимальная конфигурация

```toml
schema_version = 3
production = []
effects = []

[resources.iron]
name = "Железо"
group = "ferrous"
stage = "machine"
availability = 80.0
quality = 70.0
consumption_per_month = 25.0
storage_capacity = 2000.0

[extraction.ferrous]
intensity = 80.0
priority = 2
```

`availability` принимает значения `0–200`. Значение `100` означает обычную
доступность, `150` даёт множитель `×1.5`, а `200` — `×2`. Это позволяет
описывать исключительно богатые месторождения; качество, уклад, техника и
рабочая сила продолжают применяться отдельными множителями.

Служебных строк начала и конца больше нет. `schema_version = 3` однозначно
обозначает начало TOML; в составном input-файле конфигурация заканчивается
перед `СОСТОЯНИЕ РЕСУРСОВ`, а в отдельном `.toml` — концом файла. Неизвестное
поле является ошибкой, поэтому опечатка не будет молча потеряна.

## Произвольный новый ресурс

Глобально добавлять enum или менять Python-код не нужно:

```toml
[resources.reinforced_glass]
name = "Армированное стекло"
group = "construction"
stage = "machine"
availability = 72.0
quality = 81.0
consumption_per_month = 20.0
storage_capacity = 300.0
```

Тот же ресурс сразу можно использовать в производстве:

```toml
[[production]]
id = "reinforced_glass_production"
name = "Производство армированного стекла"
active = true
batches = 20.0
months = 24
inputs = { basic_building_materials = 2.0, silicon = 0.5 }
outputs = { reinforced_glass = 1.0 }
byproducts = { slag = 0.1 }
```

Отсутствующее поле `months` означает бессрочное правило. Число фактически выполненных партий
ограничивается сырьём и свободной вместимостью выходных складов. После попытки
выполнения срок уменьшается на фактическую длительность хода. Старое поле
`turns` всё ещё принимается при чтении как число шестимесячных периодов, но
новый вывод всегда использует календарные месяцы.

## Добыча

Ключ после `extraction` — alias фиксированной группы или зарегистрированного
ресурса. Группа имеет приоритет при совпадении имён.

```toml
[extraction.ferrous]
intensity = 80.0
priority = 2

[extraction.iron]
intensity = 100.0
priority = 1
```

`intensity` — относительная интенсивность направления от 0 до 100;
`priority` — место в очереди: `1` означает самый высокий приоритет, `2` —
следующий и так далее. Если последний используемый ранг равен `N`, вес
приоритета равен `N - priority + 1`, а итоговый вес распределения считается
как `вес_приоритета × intensity / 100`. Общая мощность равна
`расходы на ресурсодобычу × 900`. Основная доля распределяется по этим весам,
а часть автоматически направляется на незакрытое прямое потребление и сырьё
активных производственных правил. Доля реакции на спрос равна 20% при полной
обеспеченности и плавно растёт максимум до 60% при тяжёлом дефиците. Поэтому
приоритет остаётся главным стратегическим указанием, но добыча не продолжает
переполнять соль или камень, когда не хватает воды, топлива или металлов.
Вся мощность распределяется между активными правилами:
неиспользованная доля направления не исчезает, а переходит другим активным
правилам. Если активно только одно правило, любая ненулевая интенсивность
направляет в него всю доступную мощность. Заполненное направление не отнимает
долю у остальных, а мощности и работники перераспределяются заново перед
каждым месячным подшагом.
Индивидуальное правило исключает свой ресурс из группового, поэтому двойной
добычи нет.

Ресурс, являющийся выходом активного `production`, автоматически исключается
из групповой добычи. Поэтому готовые стройматериалы или сельхозинструменты не
могут одновременно «добываться» как руда. Явная операция вида
`[extraction.resource_alias]` остаётся разрешённым ручным переопределением.

`stage` задаётся в самом ресурсе и не требует дополнительных секций:

```toml
[resources.wood]
name = "Дерево"
group = "forestry"
stage = "machine"
availability = 90.0
quality = 85.0
consumption_per_month = 33.3
storage_capacity = 10000.0
```

Доступны `manual`, `steam`, `machine`, `electrified` и `mass_production`.
Если поле отсутствует в старом файле, используется `machine`. Результат всегда
остаётся в абстрактных `ед.рес.` — уклад меняет производительность формулы, а
не физическую единицу ресурса.

Коэффициенты уклада:

| Уклад | Мощность | Население в промышленности | Из пула в добычу | Зависимость от труда | Зависимость от оборудования |
| --- | ---: | ---: | ---: | ---: | ---: |
| `manual` | 0.55 | 1/3 = 33.3% | 1/3 = 33.3% | 1.15 | 0.15 |
| `steam` | 0.78 | 1/3 = 33.3% | 1/3 = 33.3% | 1.15 | 0.35 |
| `machine` | 1.00 | 1/4 = 25.0% | 1/4 = 25.0% | 1.00 | 0.60 |
| `electrified` | 1.18 | 1/5 = 20.0% | 1/4 = 25.0% | 0.82 | 0.82 |
| `mass_production` | 1.35 | 1/5 = 20.0% | 1/5 = 20.0% | 0.68 | 1.00 |

Ручной и паровой уклады используют одинаковую треть населения и направляют
треть полученного промышленного пула в добычу. Более поздние уклады требуют
меньшую долю населения, дают больше единиц, но сильнее страдают при плохой
доступности оборудования. `machine` является точкой совместимости со старым
балансом выпуска.

Старое имя `consumption` и отмеченный маркерами YAML v2 всё ещё принимаются
при чтении, но новый вывод всегда использует TOML v3 и явное
`consumption_per_month`.

## Состояние ресурсов и групп

Основная промышленная стата выводит рассчитанные данные отдельно от TOML:

```text
СОСТОЯНИЕ ГРУПП
Группа                              | Ресурсов | Добыто | Дефицит
Лесное хозяйство [forestry]         | 0        | 0       | 0
Строительные материалы [construction] | 1      | 0       | 20

СОСТОЯНИЕ РЕСУРСОВ
Ресурс                                  | Склад   | Добыто | Дефицит
Армированное стекло [reinforced_glass] | 25 / 300 | 0      | 0
```

Все ресурсные числа здесь округляются до одного знака. `Склад` — текущее
количество и вместимость. `Дефицит` — неудовлетворённая часть настроенного
расхода текущего хода.

При повторном чтении TOML имеет приоритет над снимком состояния. Если
`storage_capacity` в настройках изменена, старая вместимость из таблицы не
вызывает ошибку. Остаток сохраняется в пределах новой вместимости; излишек при
её уменьшении отбрасывается. Если в старом состоянии есть ресурс, которого уже
нет в TOML, его строка полностью игнорируется: ресурс не регистрируется обратно
и не участвует в расчётах.

## Автоматический отчёт индустриализации

После рассчитанного хода движок печатает пять дополнительных проверяемых
части. Они являются runtime-отчётом и не добавляют полей в TOML:

- `ПРОМЫШЛЕННЫЙ УКЛАД` — преобладающий этап по фактической добыче, структура
  этапов и степень механизации;
- `ПРОМЫШЛЕННАЯ ГОТОВНОСТЬ И НАПРЯЖЁННОСТЬ` — шесть межсистемных
  компонентов, итог, влияние на доход и автоматическое качество товаров;
- `РАСПРЕДЕЛЕНИЕ ДОБЫВАЮЩЕЙ МОЩНОСТИ` — приоритет, интенсивность, полученная
  доля мощности, выпуск и два самых слабых множителя формулы;
- `МАТЕРИАЛЬНЫЙ БАЛАНС` — добыча, чистый результат переработки, потребление,
  складские потери, изменение склада и дефицит каждого ресурса;
- `ПРОИЗВОДСТВО ЗА ХОД: ЦЕПОЧКИ` — реальные входы, выходы, побочные продукты
  и потери процессного выхода.

Преобладающий уклад взвешивается по добытым единицам, поэтому маленький ручной
промысел не может перевесить крупную машинную добычу только количеством
настроенных ресурсов. Степень механизации использует шкалу `0 / 25 / 50 / 75 /
100` для этапов от `manual` до `mass_production`.

`stage` влияет на выпуск добываемых `ед.рес.`, целевую долю рабочих добычи и
требования к труду и оборудованию. Он не переключается автоматически, не
создаёт целевой напряжённости и не входит в промышленную готовность напрямую.

Готовность — отдельный производный показатель страны. Компоненты сначала
нормализуются в диапазон `0–100`, затем объединяются геометрически:

```text
готовность = 100 ×
    (технологии / 100) ^ 0.20 ×
    (кадры / 100) ^ 0.20 ×
    (инфраструктура / 100) ^ 0.20 ×
    (ресурсы / 100) ^ 0.15 ×
    (институты / 100) ^ 0.10 ×
    (рынок / 100) ^ 0.15

промышленная_напряжённость = 100 - готовность
```

Технологии состоят из эффективности добычи и стандартизации; кадры — из
квалификации, образования, уровня знаний и фактического покрытия потребности
в рабочих; инфраструктура — геометрическое
среднее логистики и покрытия нормативных инфраструктурных расходов; ресурсы —
фактическое покрытие потребности; институты — эффективность аппарата и низкая
коррупция; рынок — обеспеченность ТЖН/ТНП, эффективность торговли и низкая
бедность. Геометрическая формула не позволяет полностью скрыть слабое звено
высокими значениями остальных компонентов.

Напряжённость не сохраняется как накопленный прогресс и не сбрасывается при
смене `stage`: она заново выводится из текущего состояния каждый ход. При
`100%` напряжённости промышленный доход снижается максимум на `25%`.
Качество товаров после хода полностью выводится из готовности и записывается
в экономическую стату:

```text
R = готовность / 100
высокое = 100 × R²
среднее = 200 × R × (1 - R)
низкое = 100 × (1 - R)²
```

Сумма всегда равна 100%. Старые входные доли всё ещё принимаются для
совместимости, но после первого рассчитанного хода заменяются автоматическими.

## Рабочие промышленности

Целевой пул всей промышленности:

```text
население × доля_населения_уклада × обеспеченность_рабочими / 100
```

Специалисты входят внутрь целевого пула и не добавляются поверх него;
принуждённые сначала занимают часть нормы, а при превышении нормы остаются
дополнительной рабочей силой. Целевая численность добычи равна доступному
промышленному пулу, умноженному на долю добычи из таблицы.

Для смешанной промышленности обе доли не складываются: отдельно берётся
средневзвешенное значение по фактическому распределению добывающей мощности
между операциями и ресурсами. Например, `60%` пара и `40%` машин дают
`0.6 × 1/3 + 0.4 × 1/4 = 30%` населения в промышленности и такую же долю
полученного пула в добыче.

Потребность производства считается отдельно из запланированного
материального потока по норме `250 работников / ед.рес.`. Если добыча и
производство вместе требуют больше доступного пула, обе ветви получают
одинаковую долю покрытия, а выполненные партии производства уменьшаются. В
стате видны целевая доля населения, целевая доля добычи, весь доступный пул,
занятые, резерв, нехватка и распределение между добычей и производством.

## Удобрения и орудия труда сельского хозяйства

Фиксированные группы `fertilizers` и `agricultural_tools` связаны с двумя
аграрными обеспеченностями. Месячная потребность определяется автоматически:

```text
рабочих_на_территорию = аграрные_рабочие / max(территории, 1)
удобрения = территории × (0.35 + рабочих_на_территорию / 40 000)
орудия = территории × (0.10 + рабочих_на_территорию / 2 500)
```

Если в группе несколько ресурсов, спрос делится между ними пропорционально их
`consumption_per_month`; при нулевых весах — поровну. Дефицит плавно тянет
обеспеченность к минимуму, профицит — к 100%. Минимум равен 20% при
`workers_percent >= 50`, иначе 5%. Изменение рассчитано после потребления и
влияет на выпуск сельского хозяйства со следующего хода.

Колонка `Перераб.` является чистым материальным потоком производства
(`выходы + побочные − входы`), а `Хран.потери` вычисляются из точного
расхождения склада до и после хода.

Пример сокращённого отчёта:

```text
╫ ПРОМЫШЛЕННЫЙ УКЛАД ╫
╫ Преобладающий этап            ╫ Машинный              ╫
╫ Степень механизации           ╫ 50.0%                  ╫

╫ ПРОМЫШЛЕННАЯ ГОТОВНОСТЬ И НАПРЯЖЁННОСТЬ ╫
╫ Технологии     ╫ 74.4%  ╫ 20% ╫
╫ Кадры          ╫ 72.4%  ╫ 20% ╫
╫ Инфраструктура ╫ 52.0%  ╫ 20% ╫
╫ Ресурсы        ╫ 100.0% ╫ 15% ╫
╫ Институты      ╫ 99.6%  ╫ 10% ╫
╫ Рынок          ╫ 96.1%  ╫ 15% ╫
╫ Промышленная готовность    ╫ 77.0%  ╫
╫ Промышленная напряжённость ╫ 23.0%  ╫
╫ Множитель пром. дохода     ╫ ×0.943 ╫

╫ РАСПРЕДЕЛЕНИЕ ДОБЫВАЮЩЕЙ МОЩНОСТИ ╫
╫ Чёрные металлы [ferrous] ╫ Машинный ╫ 2 / 85% ╫ 10.2% / 290.8 ╫ 74.4 ╫ технологии 63%, выход продукции 72% ╫

╫ МАТЕРИАЛЬНЫЙ БАЛАНС ╫
╫ Железо [iron] ╫ Машинный ╫ 74.4 ╫ 0.0 ╫ 60.0 ╫ 2.6 ╫ +11.8 ╫ 0.0 ╫
```

## Настраиваемые эффекты

Эффект содержит только `id`, список зависимостей, список целевых стат и одну
формулу. Одна формула применяется отдельно к каждой цели; `target` означает
текущее значение этой цели, а результат формулы — прибавку к нему.

```toml
[[effects]]
id = "freshwater_population_growth"
dependencies = [{ resource = "fresh_water" }]
targets = ["population_growth"]
formula = "-target * resources.fresh_water.deficit * 0.2"

[[effects]]
id = "construction_infrastructure_expenses"
dependencies = [{ group = "construction" }]
targets = ["infrastructure_expenses"]
formula = "target * (0.4 * groups.construction.deficit - min(0.25 * groups.construction.surplus, 0.2))"

[[effects]]
id = "hydrocarbons_transport"
dependencies = [{ group = "hydrocarbons" }]
targets = ["logistic", "trade_efficiency"]
formula = "-target * groups.hydrocarbons.deficit * 0.08"

[[effects]]
id = "glass_safety"
dependencies = [{ resource = "reinforced_glass" }, { group = "construction" }]
targets = ["industrial_accident_chance", "population_epidemic_chance"]
formula = "target * (0.12 * groups.construction.deficit - min(0.05 * resources.reinforced_glass.surplus, 0.2))"
```

Каждая объявленная зависимость предоставляет только два нормированных числа:

```text
resources.<alias>.deficit
resources.<alias>.surplus
groups.<alias>.deficit
groups.<alias>.surplus
```

Для ресурса со спросом `D`:

```text
deficit = неудовлетворённый_расход / D
surplus = остаток_на_складе / D
```

При нулевом спросе обе величины равны нулю: у движка нет масштаба, относительно
которого можно назвать склад дефицитом или профицитом. Для группы числители и
спрос суммируются по её ресурсам со спросом.

Разрешены числа, `target`, `+`, `-`, `*`, `/`, `**`, а также `min`, `max` и
`abs`. Выражение разбирается через AST без Python `eval`; доступ к файлам,
импортам, методам и необъявленным зависимостям запрещён.

Целью может быть любая существующая числовая стата из разделов `economy`,
`industry`, `agriculture`, `inner_politics` и `probabilities`. Для уникального
имени раздел не нужен:

```toml
targets = [
    "trade_efficiency",
    "logistic",
    "food_diversity",
    "contentment",
    "research_success_chance",
    "industrial_accident_chance",
]
```

Если одно имя есть в нескольких разделах, программа попросит уточнить раздел:

```toml
targets = ["industry.expected_wastes", "agriculture.expected_wastes"]
```

Отдельно сохраняются два удобных специальных alias:

- `population_growth` — рассчитанный прирост до остальных демографических
  множителей;
- `infrastructure_expenses` — эффективные расходы на инфраструктуру.

Поправка к `population_growth` отдельно видна в строке `Поправка формул
ресурсов` демографического отчёта. Ниже отчёт показывает все последующие
множители, итоговый прирост, УНЧС, смерти от недоедания и конечное население.

Вторая цель не переписывает исходную стату расходов. Её результат входит в
отдельную строку `Поправка расходов от ресурсов` бюджетного отчёта и затем в
общие расходы.

Целочисленные статы округляются до целого. Ограничения конкретного поля
соблюдаются автоматически: вероятность или показатель с диапазоном `0..100`
не выйдет за этот диапазон, а казна без нижнего ограничения может остаться
отрицательной. Списки, словари, вложенные объекты и несуществующие показатели
указывать нельзя. Производные показатели изменяются после собственного
пересчёта: этап выбирается движком автоматически и не задаётся в TOML.

Если в модель страны добавить новую числовую стату, её имя сразу станет
доступно в `targets`; отдельный enum или реестр пополнять не требуется.

## Проверка загрузки и применения эффектов

`create_basic_country.py` без дополнительных аргументов создаёт страну, но не
рассчитывает ход. Поэтому основной выходной файл честно показывает, что
настроенные эффекты ещё не применялись:

```text
ЭФФЕКТЫ ПРОМЫШЛЕННОСТИ
freshwater_society:
  contentment                : ожидает расчёта хода
  food_diversity             : ожидает расчёта хода
  population_epidemic_chance : ожидает расчёта хода
```

Чтобы одновременно создать страну, рассчитать ход и увидеть результат:

```bash
uv run python create_basic_country.py --turns 1 --seed 1
```

В основной стате появится отдельный читаемый отчёт без конфигурационных полей:

```text
ЭФФЕКТЫ ПРОМЫШЛЕННОСТИ
freshwater_society:
  contentment                : 89.0 -> 89.0 (+0.0)
  food_diversity             : 96.7 -> 96.7 (+0.0)
  population_epidemic_chance :  1.5 ->  1.5 (+0.0)
```

Нулевая поправка означает не потерю эффекта, а отсутствие дефицита или
профицита, на которые ссылается формула. Редактируемая формула, зависимости и
полный список целей остаются в отдельном `*_industry_settings.toml`.

## Перенос старого YAML

Старый блок между строками `НАСТРОЙКА ПРОМЫШЛЕННОСТИ YAML` и
`КОНЕЦ НАСТРОЙКИ ПРОМЫШЛЕННОСТИ` всё ещё можно прочитать напрямую. Для
одноразового преобразования всего input-файла без этих строк:

```bash
uv run python convert_industry_config.py old_input.txt new_input.txt
```

Для отдельного файла настроек:

```bash
uv run python convert_industry_config.py old_settings.txt new_settings.toml --settings-only
```

Исходный файл не перезаписывается, если явно не передать тот же путь.

## Python API

```python
from stats.industry_components import (
    ExtractionGroup,
    ResourceRegistration,
    ResourceType,
)

glass = ResourceType("reinforced_glass")
industry.register_resource(
    ResourceRegistration(
        resource=glass,
        name="Армированное стекло",
        group=ExtractionGroup.CONSTRUCTION,
        stockpile=25,
        storage_capacity=300,
        consumption_per_month=20,
    )
)
```

Встроенные `ResourceType.IRON` и подобные константы оставлены как удобные
совместимые alias, но не образуют закрытый перечень.
