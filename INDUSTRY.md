# Промышленность и ресурсы

Один ход равен шести месяцам. Добыча считается шестью месячными шагами,
после неё выполняются производственные правила и покрывается обычный расход.

## Регистрация групп и ресурсов

Группа, ресурс, текущее состояние и добыча — разные сущности. Регистрация
ресурса не содержит переключатель активности, добывающую технику или
работников. Сам факт регистрации означает, что ресурс есть у страны.

```python
from stats.industry_components import ResourceRegistration, ResourceType

industry.register_resource(
    ResourceRegistration(
        resource=ResourceType.IRON,
        stockpile=100,
        storage_capacity=2_000,
        accessibility=80,
        quality=70,
        consumption_per_turn=25,
    )
)
```

`register_resource` автоматически регистрирует штатную группу ресурса. Группу
также можно добавить явно через `register_resource_group`. Склад проверяется:
его содержимое не может превышать вместимость.

## Добыча без ручного распределения работников

Добыча задаётся отдельно для группы или для одного ресурса:

```python
from stats.industry_components import ExtractionGroup, ExtractionOperation

industry.set_extraction_operation(
    ExtractionOperation(
        target=ExtractionGroup.FERROUS,
        intensity=80,
        priority=2,
    )
)
```

Для отдельного ресурса передаётся его alias:

```python
industry.set_extraction_operation(
    ExtractionOperation(
        target=ResourceType.IRON,
        intensity=100,
        priority=3,
    )
)
```

Внешнее правило содержит только два управленческих параметра:

- `intensity` — загрузка направления от 0 до 100%;
- `priority` — относительная доля общих добывающих ресурсов страны.

Абсолютную мощность, технику и работников человек не вводит. Общий годовой
потенциал рассчитывается из уже существующих расходов на ресурсодобычу:
`расходы × 300 абстрактных единиц`. Приоритеты делят этот потенциал между
правилами, а интенсивность определяет, какая доля выделенного потенциала
действительно используется. Затем движок учитывает рабочую силу, доступность,
качество, общую эффективность промышленности и вероятностные коэффициенты.

Внутри группового правила добыча сначала идёт на ресурсы с неудовлетворённым
спросом, затем — пропорционально свободному месту на складах. Индивидуальное
правило ресурса заменяет для него групповое и не удваивает добычу.

## Производственные правила

Правило может относиться к одному выходному ресурсу или ко всей группе. Входы и
выходы остаются явными, поэтому расчёт полностью проверяем:

```python
from stats.production_components import ProductionRule

industry.set_production_rule(
    ProductionRule(
        rule_id="iron_parts",
        name="Железные детали",
        target_resource=ResourceType.BASIC_BUILDING_MATERIALS,
        batches=50,
        turns_remaining=3,
        inputs={ResourceType.IRON: 2},
        outputs={ResourceType.BASIC_BUILDING_MATERIALS: 1},
        byproducts={ResourceType.SLAG: 0.1},
    )
)
```

Для группового правила используется `target_group`. Все его выходы должны
относиться к этой группе. Фактическое число партий ограничивается сырьём и
свободным складом. `turns_remaining=None` означает бессрочное правило.

## Внешний текстовый формат

Идентификаторы в квадратных скобках стабильны. Отображаемые русские имена
нужны человеку, alias — парсеру.

```text
НАСТРОЙКА ПРОМЫШЛЕННОСТИ
ГРУППЫ
Группа Чёрные металлы [ferrous]
Группа Строительные материалы [construction]
РЕСУРСЫ
Ресурс Железо [iron] | группа=ferrous | доступность=80 | качество=70 | расход=25 | склад=2000
Ресурс Базовые стройматериалы [basic_building_materials] | группа=construction | доступность=100 | качество=100 | расход=0 | склад=1000
ДОБЫЧА
Добыча ferrous | интенсивность=80 | приоритет=2
ПРАВИЛА ПРОИЗВОДСТВА
Правило Железные детали [iron_parts] | цель=ресурс[basic_building_materials] | статус=активно | партий=50 | ходов=3 | вход=iron:2 | выход=basic_building_materials:1 | побочно=slag:0.1
КОНЕЦ НАСТРОЙКИ ПРОМЫШЛЕННОСТИ
```

Это отдельный файл настроек. Его разделы имеют разные роли:

- `ГРУППЫ` и `РЕСУРСЫ` — пользовательская регистрация;
- `ДОБЫЧА` — интенсивность и относительные приоритеты направлений;
- `ПРАВИЛА ПРОИЗВОДСТВА` — преобразования на один или несколько ходов.

`склад=2000` задаёт вместимость. Текущее количество на складе не является
настройкой и выводится в основной стате как `100 / 2000`.

```text
СОСТОЯНИЕ РЕСУРСОВ
Ресурс                                    | Склад      | Добыто | Дефицит
----------------------------------------- | ---------- | ------- | -------
Железо [iron]                             | 100 / 2000 | 0       | 0
Базовые стройматериалы [basic_building_materials] | 0 / 1000 | 0 | 0
```

Рабочая сила также не настраивается в этом файле. Число обычных работников и
специалистов рассчитывается в начале хода и остаётся видимым в разделе
`РЕСУРСОДОБЫЧА` основной статы.

Все числа ресурсного интерфейса выводятся максимум с одним знаком после
запятой. Состояние и настройки безопасно читаются обратно вместе; ошибка
одного цикла сохранения не превышает `0.05` единицы ресурса.

Предыдущий смешанный формат не поддерживается.

После обязательных полей обычный `country_creator` предлагает вставить
настройки и, при создании страны, начальное состояние ресурсов. Если первая
строка пустая, страна создаётся без зарегистрированных ресурсов. Скрипт
`create_basic_country.py` сохраняет основную стату и настройки промышленности
в разные файлы. В `moves_skipper` они также вводятся отдельными секциями.
Ограждённые Markdown-блоки читаются до закрывающей рамки. Ввод без рамки также
сохраняет одиночные внутренние пустые строки и заканчивается только после
финальных полей раздела.

## Внутренняя детализация производства

Результат выполнения правил не входит внутрь обычной пользовательской статы.
После хода приложение печатает его отдельным блоком; через API тот же текст
возвращает `render_production_results()`:

```text
ПРОИЗВОДСТВО ЗА ХОД
Железные детали [iron_parts]: план 50.0, выполнено 42.5 партий, осталось ходов 2
  Взято: Железо 85.0
  Выпущено: Базовые стройматериалы 36.1
  Побочно: Шлак 10.6
```

Следом приложение печатает `render_configuration()` с уже уменьшенными
сроками правил. Именно этот блок нужно переносить в настройки следующего хода.

Вероятности крупных событий только выводятся пользователю и не применяются
движком автоматически.
